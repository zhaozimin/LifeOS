# 备份与恢复

**先说最重要的一句：这个版本没有「一键恢复」。备份要你自己动手，而且方法不对会丢数据。**

这篇告诉你正确的做法。全文用的安装位置都是默认的那个：

```text
~/Library/Application Support/LifeOS/app
```

如果你装在别的地方，把下面所有命令里的这段路径换成你自己的。

---

## 一、你的数据到底在哪

全都在这一个目录里面：

```text
~/Library/Application Support/LifeOS/app/server/runtime/
```

里面长这样：

| 位置 | 是什么 |
| --- | --- |
| `config.json` | 端口和**访问密钥**（等于你两本账本的钥匙） |
| `connection-info.txt` | 那行带密钥的面板地址 |
| `time/time.sqlite3` | **时间账本** |
| `finance/finance.sqlite3` | **金钱账本** |
| `finance/attachments/` | 你拍的**票据照片**，一笔账一个文件夹 |
| `time/audit/`、`finance/audit/` | 历史快照（下面第四节专门讲） |

**记住一件事：账本文件不止你看到的那一个 `.sqlite3`。** 它旁边还会有两个跟屁虫文件，名字是 `time.sqlite3-wal` 和 `time.sqlite3-shm`。最近写进去的数据可能还躺在 `-wal` 里面，还没并进主文件。

所以——

> **只拷 `.sqlite3` 一个文件 = 会丢数据。**
> 永远整个 `runtime` 目录一起拷。

---

## 二、怎么正确备份

一共四步。全程五分钟，建议每周做一次，重要的月份做完账之后再做一次。

### 第 1 步：停掉服务

拷贝之前必须先让它停下来，否则你拷到的可能是写了一半的账本。把下面这行粘到终端里，回车：

```bash
launchctl bootout gui/$(id -u)/com.lifeos.node
```

**你会看到**：没有任何输出，就是成功了。

**看不到怎么办**：如果它说 `No such process`，说明服务本来就没在跑，那正好，直接进行下一步。

### 第 2 步：确认它真的停了

把下面这行粘到终端里，回车：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:59418/v1/health
```

**你会看到**：`000`。这表示没人应答，服务确实停了，可以安全拷贝。

**看不到怎么办**：如果看到 `401` 或 `200`，说明还有进程在跑（可能是你自己在别的终端窗口里前台启动的）。把那个窗口按 `Control + C` 停掉，再跑一次这行。

### 第 3 步：整个目录拷走

把下面这两行一起粘到终端里，回车（日期会自动填今天）：

```bash
cd "$HOME/Library/Application Support/LifeOS/app/server"
cp -Rp runtime ~/Desktop/LifeOS备份-$(date +%Y%m%d)
```

**你会看到**：没有输出就是成功了。桌面上会多出一个像 `LifeOS备份-20260803` 这样的文件夹。

`-Rp` 里的 `p` 很重要：它保留文件权限，让备份里的密钥文件仍然只有你能读。

**这份备份里含有你的访问密钥。** 放进网盘、发给别人、传到公司电脑之前，想清楚。

### 第 4 步：把服务起回来

把下面这行粘到终端里，回车：

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.lifeos.node.plist
```

然后确认它活过来了：

```bash
python3 "$HOME/Library/Application Support/LifeOS/app/skills/zzm-lifeos/scripts/timectl.py" health
```

**你会看到**：一大段 JSON，里面同时有 `"time"` 和 `"finance"` 两块。看到这两块就没事了。

## 三、怎么恢复

用在这些时候：硬盘换了、误删了、想回到上周的状态。

**恢复的第一原则：不要覆盖，要换名。** 万一备份本身有问题，你还得能退回来。

### 第 1 步：停掉服务

```bash
launchctl bootout gui/$(id -u)/com.lifeos.node
```

同样，跑一次第二节第 2 步那条 `curl`，确认返回 `000` 再往下走。

### 第 2 步：把现在的 runtime 改个名留着

**不要删。** 把下面两行一起粘到终端里，回车：

```bash
cd "$HOME/Library/Application Support/LifeOS/app/server"
mv runtime runtime-换下来的-$(date +%Y%m%d%H%M)
```

### 第 3 步：把备份整个搬回去

把下面这行粘到终端里，回车（把日期换成你要恢复的那份备份）：

```bash
cp -Rp ~/Desktop/LifeOS备份-20260803 "$HOME/Library/Application Support/LifeOS/app/server/runtime"
```

### 第 4 步：起服务

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.lifeos.node.plist
```

### 第 5 步：核对（这一步不能省）

先看程序层面：

```bash
python3 "$HOME/Library/Application Support/LifeOS/app/skills/zzm-lifeos/scripts/timectl.py" health
```

**你会看到**：`"time"` 和 `"finance"` 两块都在，两个 `dbPath` 都指向 `.../LifeOS/app/server/runtime/` 下面。

然后**一定要用眼睛看一遍面板**：打开 `http://127.0.0.1:59418/dashboard/`，翻到你记得清楚的某一天，确认时间条目和账目都在、金额对得上。

程序说「健康」只代表两本账本挂上了，**不代表里面的内容是你想要的那一份**。这一眼必须你自己看。

### 万一恢复出来的不对

第 2 步留下的 `runtime-换下来的-...` 还在原地。停服务，把当前 `runtime` 改名，把它改回 `runtime`，再起服务。你没有失去任何东西——这就是不许直接删的原因。

### 恢复完之后，密钥可能变了

如果你恢复的是**另一台电脑上的备份**，里面的 `config.json` 带的是那台电脑的访问密钥。浏览器里存的旧密钥会失效，面板会重新问你要。跑这行把新的取出来：

```bash
cat "$HOME/Library/Application Support/LifeOS/app/server/runtime/connection-info.txt"
```

## 四、关于「历史快照」，有三件事你必须知道

LifeOS 在记一笔、改一笔、删一笔时，都会顺手给那本账本拍一张**整库照片**，存在这里：

```text
server/runtime/time/audit/snapshots/
server/runtime/finance/audit/snapshots/
```

这是它的审计链，用来证明「哪一条记录在什么时候被谁改成了什么」。但它有三个必须说清楚的边界：

### 1. 快照**不包含票据照片**

快照只拍数据库文件，不拍 `finance/attachments/` 里的图片。

**后果**：如果你哪天拿某张快照回退账本，会出现「账目里挂着一张票据，点开却打不开文件」——因为那张图从来就没被快照带走过。

**所以**：真正的备份永远是第二节那个「整个 runtime 目录一起拷」的做法。快照不是备份的替代品。

### 2. 快照**只增不减，会一直长**

这个版本**没有任何自动清理**。你记一年账，`snapshots/` 里就会累积一年份的整库副本，每一份都是当时账本的完整大小。磁盘占用只会往上走。

想看看它现在多大，把下面这行粘到终端里，回车：

```bash
du -sh "$HOME/Library/Application Support/LifeOS/app/server/runtime"/*/audit/snapshots
```

**你会看到**：两行，分别是时间和金钱两本账的快照总大小。

### 3. 产品里**没有任何一键恢复**

面板上没有「恢复到某个时间点」的按钮，命令行里也没有。快照文件在那儿，但把它变回你的账本这件事，目前只能靠第三节那套手动流程（把某个快照文件改名成 `time.sqlite3` 放回 `runtime/time/`，且要先删掉旁边的 `-wal`、`-shm`）——**这属于高风险操作，做之前务必先按第二节完整备份一次**。

### 想清理旧快照

**先备份，再清理。** 顺序不能反。

第一步，看看都有些什么（只是看，不删）。把下面这行粘到终端里，回车：

```bash
ls -lt "$HOME/Library/Application Support/LifeOS/app/server/runtime/finance/audit/snapshots" | head -20
```

**你会看到**：按时间从新到旧排列的一堆 `.sqlite3` 文件。

第二步，删掉 90 天以前的。把下面这行粘到终端里，回车：

```bash
find "$HOME/Library/Application Support/LifeOS/app/server/runtime"/*/audit/snapshots -name '*.sqlite3' -mtime +90 -delete
```

**删掉快照会丢什么、不会丢什么**：

- **不会丢**：你的账本本身，以及每条记录的修改痕迹（谁在什么时候把什么改成了什么）。这些是记在账本文件**里面**的，面板上的「修改历史」读的就是它，删快照文件动不到。
- **会丢**：那几天的「整库照片」。也就是说，你没法再回到那几天的完整状态了。

**有四种操作不在上面这套机制里**：把一笔账标成「已报销」、撤销报销、上传票据、删除票据。这四件事**既不拍快照，也不写进修改历史**——事后你在面板上查「这笔什么时候被标成已报销的」，那里会是空的，也没有对应时点的整库照片可回退。账目本身的记一笔/改一笔/删一笔不受影响，照常拍照、照常留痕。

服务运行时删也没问题，但保险起见还是建议按第二节先停服务。

## 五、一条必须知道的隐私事实

**在 LifeOS 里「删除」一条记录，不是把它抹掉，是给它盖个「已删除」的章。**

- 被删的记录仍然留在账本文件里，只是不再显示、不再计入统计。
- 面板上的「导出全部数据」会把已删除的记录**一并导出**（导出成功时会明确告诉你「含 N 条已删除记录」）。
- 更重要的是：删除**之前**拍的那些历史快照，里面完完整整地留着这条记录的原样。

这是审计链的设计，为的是让「账本被改过什么」永远查得清。但你需要知道它的另一面：

> **想让某条记录真正从这台电脑上消失，光在面板里删是不够的。**
> 你还得删掉包含它的那些历史快照（见上一节），以及你自己做过的所有备份副本。

## 六、一页纸速查

| 我想…… | 怎么做 |
| --- | --- |
| 备份 | 停服务 → 确认 `000` → `cp -Rp runtime 到别处` → 起服务 |
| 恢复 | 停服务 → 当前 runtime **改名**别删 → 备份整个拷回来 → 起服务 → health + 肉眼核对 |
| 停服务 | `launchctl bootout gui/$(id -u)/com.lifeos.node` |
| 起服务 | `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.lifeos.node.plist` |
| 找回密钥 | `cat .../server/runtime/connection-info.txt` |
| 看快照占了多少 | `du -sh .../runtime/*/audit/snapshots` |

绝对不要做的三件事：

1. 只拷 `.sqlite3` 单个文件（`-wal` 里的数据会丢）
2. 服务还在跑的时候拷贝
3. 恢复时直接删掉当前 `runtime`（错了就退不回来了）

这个版本还做不到什么，见《[已知问题](已知问题.md)》。
