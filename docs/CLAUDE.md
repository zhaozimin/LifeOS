成员清单
安装指南.md: 面向零技术背景用户的唯一安装入口；三条路径（引导 skill / Release ZIP / 源码）收敛到同一个安装位置与同一套验收动作，每步都写「你会看到什么」和「看不到怎么办」。装完之后的取密钥、换指针、卸载与 Tailscale 也留在这里，因为它们是同一条决策链的下游。
备份与恢复.md: 数据主权的操作面。核心是两条铁律——WAL 决定了「只拷单个 .sqlite3 会丢数据」，恢复时「改名不删」才留得住退路；审计快照的三个边界（不含附件 / 无保留策略 / 无回滚入口）与「删除是逻辑删除」这条隐私事实也在此向用户交底。
已知问题.md: 当前版本能力边界的完整清单，按「可能咬到用户」的程度排序。它是对外承诺的负面清单，不是路线图；每一条否定式声明都在 test_docs_contract.py 里有一条断言把它钉在源码上。
test_docs_contract.py: 手册与代码的同构闸门。手册是代码的产物，而代码变了手册不会自己变——本项目已因此作废过一整篇 API 文档，所以路径、端口、运行时布局与每一条「做不到」都在这里对着真实源码断言：功能一旦被实现，先红的是测试而不是用户的信任。

法则：文档必须指向真实代码和可复现证据，不能把计划写成已完成的事实。四份用户文档共享同一套事实源（安装脚本、Ledger 接线、域常量与路由契约），任何一处改动都要让 test_docs_contract.py 重新变绿才算完成。

跑：`cd docs && python3 -m unittest test_docs_contract -v`
